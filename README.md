# Обрезка и дистилляция модели

## Сравнение распределений на тестовой выборке

При `distribution_comparison.enabled: true` основной `python main.py` выполняет
сравнение после успешной дистилляции отдельным процессом (память обучения к этому
моменту освобождена). `false` отключает этот этап. В конфиге по умолчанию он включён.
При `models: null` пути автоматически берутся из `student_model_path` (обрезанная
модель) и `output_dir/student` (обученная модель). Можно явно задать список моделей
для оценки уже сохранённых результатов. Отдельный запуск скрипта выполняет оценку
независимо от флага `enabled`.

Полный JSON теперь содержит метрики каждого токена, примерные распределения
вероятностей, число параметров моделей и настройки расчёта. `token_statistics`
включает среднее, стандартное отклонение, медиану, минимум, максимум, p05 и p95
для каждой метрики. Дополнительно вычисляются энтропия студента и точность top-1
предсказаний обеих моделей относительно эталонных токенов.

Рядом с JSON создаётся папка `<имя_отчёта>_artifacts`:

- `summary.csv`: итоговые характеристики моделей;
- `examples.csv`: характеристики каждого примера;
- `tokens.csv`: характеристики каждого токена ответа;
- `token_metric_histograms.png`: гистограммы KL, кросс-энтропии, энтропий и NLL
  по токенам всей выборки; для моделей используются общие границы столбцов;
- `model_0_token_probabilities.png`, `model_1_token_probabilities.png`: вероятности
  токенов на нескольких одинаковых контекстах учителя и соответствующей модели.

Диаграммы вероятностей показывают объединение top-k токенов обеих моделей,
эталонный токен и суммарную массу остальных токенов. `top_k` и `snapshot_positions`
управляют только этими иллюстрациями, все метрики считаются по полному словарю.
Для снимков используются первые позиции ответа первого тестового примера;
они иллюстрируют отдельные контексты, а не всю выборку. `save_histograms: false`
отключает оба вида PNG. Для графиков нужен matplotlib, уже используемый обучением.

Отдельный скрипт `compare_distributions.py` не запускает обучение и не меняет веса:

```console
python compare_distributions.py --config config.yaml
```

В `config.yaml` настройте блок `distribution_comparison`: `test_file` с записями
`input`/`output`, список `models` с локальными папками обрезанной и обученной
моделей, `output_file`. Учитель выбирается из общих настроек `teacher_model_path`
(либо `merged_teacher_path`, если включён `merge_adapter`; объединение скрипт
оценки сам не выполняет). Для уже готового учителя используйте
`merge_adapter: false` и путь к `teacher_merged`.

Для вашего адаптера используется `prompt_template: chat`, `enable_thinking=False`
и тестовый файл `ru_simple_gsd_conll_short_test.json`. `base` соответствует
шаблону `### Input / ### Answer`. Нужны эталонные ответы в обученном формате,
не JSONL с результатами инференса. Тестовая выборка должна быть отложенной:
проверьте, что она не использовалась ранее как обучающая или для подбора настроек.
В исходном конфиге `local_val_file` указывает на test-файл; для независимой оценки
перенесите валидацию на dev-файл и используйте отдельный test-набор.

Все модели получают одинаковые токены запроса и эталонного ответа (teacher forcing).
Запрос исключается из метрик, padding не добавляется. По умолчанию включены
разделители окончания ответа из chat-шаблона и EOS сохранённого токенизатора,
включая legacy EOS `2` вашего адаптера. `append_eos: false` отключает только
дополнительный EOS, но не разделители chat-шаблона. Словари и ID токенов должны
совпадать; отдельные токенизаторы моделей используются для проверки словаря,
а последовательности формирует токенизатор учителя.

Результат JSON содержит итог по каждой модели и значения для каждого примера:

- `cross_entropy`: H(учитель, студент), по полному словарю;
- `teacher_entropy`: H(учитель), для интерпретации кросс-энтропии;
- `kl`: KL(учитель || студент);
- `teacher_nll`, `student_nll`: кросс-энтропия по эталонным токенам;
- `top1_agreement`: доля совпадений наиболее вероятного токена;
- `tokens`: число оценённых токенов ответа.

Используются натуральные логарифмы, температура 1 и среднее, взвешенное по числу
токенов, а не по числу предложений. Вероятности не ограничиваются top-k.
Слишком длинные примеры вызывают ошибку с просьбой увеличить `max_length`,
без скрытого обрезания ответов. Для пробного запуска задайте `max_examples: 10`,
для всей выборки — `null`. Учитель и одна сравниваемая модель одновременно
находятся на выбранном устройстве; расчёт метрик идёт на CPU частями по словарю
всех токенов, по 32 позиции за раз. CUDA использует float16, CPU — float32.

`python main.py` последовательно запускает обрезку слоёв (`auto_prune.py`)
и дистилляцию студента (`Qwen2Distillation.py`). Оба этапа читают `config.yaml`
и используют один способ загрузки учителя.

## Объединение адаптера с базовой моделью

Для сохранённого PEFT/LoRA-адаптера укажите в `config.yaml`:

```yaml
merge_adapter: true
adapter_model_path: '/content/drive/MyDrive/my_adapter'
adapter_base_model_path: null
merged_teacher_path: '/content/drive/MyDrive/teacher_merged'
teacher_config_path: null
teacher_tokenizer_path: null
teacher_local_files_only: false
```

Папка адаптера должна содержать `adapter_config.json` и
`adapter_model.safetensors` от одного checkpoint. База берётся из поля
`base_model_name_or_path` в `adapter_config.json`. Если там старый локальный
путь, задайте актуальную папку или точный ID исходной модели в
`adapter_base_model_path`. Для отдельного полного файла весов базы также
можно использовать `teacher_config_path`.

Токенизатор берётся из папки адаптера, если там есть его файлы, иначе —
из базовой модели. `teacher_tokenizer_path` позволяет задать источник явно.
При несовместимых или повреждённых файлах токенизатора объединение
останавливается, без автоматической замены словаря.

Установите зависимости в окружение обучения (в Colab добавьте `!` перед командой):

```console
pip install peft transformers safetensors accelerate pyyaml
```

Запустите весь пайплайн:

```console
python main.py
```

Сначала запускается `merge_adapter.py`, затем обрезка и дистилляция используют
`merged_teacher_path` как папку учителя, включая сохранённые конфигурацию и
токенизатор. `teacher_model_path` при включённом объединении не используется
для выбора базы. Исходный `config.yaml` скрипты не переписывают.
Объединение выполняется на CPU в float32, результат сохраняется в bfloat16
и safetensors. Нужна оперативная память для полной базовой модели.

Только объединение, без запуска обучения:

```console
python merge_adapter.py
```

Этот отдельный запуск выполняет объединение независимо от флага
`merge_adapter`; также принимает `--config путь/к/config.yaml`.

Папка `merged_teacher_path` должна быть новой или пустой: существующие
результаты не перезаписываются. Для повторного обучения с готовой моделью
установите:

```yaml
merge_adapter: false
teacher_model_path: '/content/drive/MyDrive/teacher_merged'
teacher_config_path: null
teacher_tokenizer_path: null
teacher_local_files_only: true
```

При запуске этапов по отдельности с `merge_adapter: true` сначала выполните
`python merge_adapter.py`, чтобы папка полного учителя уже существовала.
Поддерживаются PEFT-адаптеры с операцией `merge_and_unload`, в частности LoRA.

## Локальный учитель в формате safetensors

Для папки Transformers с `config.json`, файлами токенизатора и весами:

```yaml
teacher_model_path: 'D:/models/teacher'
teacher_local_files_only: true
```

Поддерживаются как `model.safetensors`, так и несколько частей весов
с индексом `model.safetensors.index.json`. Для нескольких частей указывайте
именно папку, а не отдельную часть.

Для отдельного полного файла весов с произвольным именем:

```yaml
teacher_model_path: 'D:/models/teacher/custom.safetensors'
teacher_config_path: null
teacher_tokenizer_path: null
teacher_local_files_only: true
```

По умолчанию `config.json` и токенизатор ищутся в папке этого файла.
В `.safetensors` нет описания архитектуры и токенизатора, поэтому одного
файла весов недостаточно. Если сопутствующие файлы лежат отдельно:

```yaml
teacher_model_path: 'D:/weights/teacher.safetensors'
teacher_config_path: 'D:/models/original/config.json'
teacher_tokenizer_path: 'D:/models/original'
teacher_local_files_only: true
```

Конфигурация должна соответствовать архитектуре и размерам весов,
токенизатор — словарю учителя. Нужен полный checkpoint в формате
Transformers, а не LoRA-адаптер или checkpoint стороннего формата.
Неполные или несовместимые веса приводят к ошибке загрузки.

Идентификаторы Hugging Face по-прежнему поддерживаются, в том числе
в `teacher_config_path` и `teacher_tokenizer_path`. При
`teacher_local_files_only: true` они загружаются только из локального кеша.
Локальные папки загружаются без обращения к Hub независимо от этого флага.
Относительные пути считаются от рабочей папки запуска. Для Windows удобно
использовать `/` в путях, как в примерах выше.

Запуск обучения требует прежних зависимостей проекта, в том числе PyTorch,
Transformers и safetensors, а также настроенных путей к данным в `config.yaml`.
Этап обрезки использует CUDA, как и раньше.

Локальные данные читаются общим загрузчиком `data_loading.py`: поддерживаются
обычный JSON-массив записей, один JSON-объект и JSONL (одна запись на строку).
Поле со строкой текста задаётся через `dataset_text_field: "text"`.
Например, для `[{"sentence": "Пример предложения"}]` укажите
`dataset_text_field: "sentence"`. Списки токенов и другие структуры не
преобразуются в текст автоматически. Пустые данные, ошибочный JSON и
отсутствие нужного поля вызывают понятную ошибку до загрузки весов.

Проверка выбора источников и обработки ошибок без окружения обучения:

```console
python -m unittest discover -s tests
```
